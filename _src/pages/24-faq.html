Objections, answered plainly

The questions people actually ask before they install something that touches their partner payments.

Who owns the data?

You do, in a database on a server you control. Refficks is self-hosted with Docker Compose — there is no copy of your partner data on infrastructure we run, because we do not run any infrastructure for you.

Precisely: multi-tenant isolation is still a tested property inside your deployment — every resource carries a test proving one organization cannot read another’s data — which matters the moment you run more than one programme.

Does the AI see my partners’ bank details?

No, and not as a matter of policy. Partner payout details never reach the model, and there is a test asserting their absence from the context it is given.

More broadly: the assistant cannot approve, reverse or suspend anything. The interface it is reached through has no tools, no database access and no write path, so there is no instruction that makes it able to move money.

Precisely: the assistant is off by default, and you can switch it off for your organization even when the deployment it runs on has it enabled.

Can an automation pay someone?

No. An automation may do exactly three things: send an email, add a tag, or enrol a partner in a campaign. It cannot touch money. Ever.

Refficks does not move money at all, in fact. It builds the payout batch, tells you who cannot be paid and why, and exports a CSV your bank can use. There is always a step where a person can say no.

What happens to my LeadDyno history?

Your partners come across with their contact details, coupon codes and status. Their historical commission totals come across as LeadDyno’s reported figures, labelled as such on the partner record.

They are not written into the Refficks ledger. The ledger only holds money it can explain — every entry stores the arithmetic that produced it and the attribution decision behind that — and an imported total has none of that behind it. So your ledger starts clean on the day you start, and the old numbers sit beside it as context.

That is a real trade, and it is the honest one. The long version is on the migration page.

Do you store IP addresses?

Refficks never stores a raw IP address. Fraud signals run on salted hashes, and Do Not Track is respected by default.

Precisely: this site follows the same rule. No cookies, no trackers, and nothing that would need a consent banner. Privacy.

What is not built yet?

Stripe is the payment integration today, alongside the generic REST API and the JavaScript tracker. Paddle and others are planned and not present.

The affiliate module is what ships. Referral, creator, ambassador, agency and reseller programmes exist as architecture, not as features you can run a programme on.

There is no hosted version — self-hosted only.

The full inventory is on the roadmap, in three states: shipping, architecture only, and not built. Nothing on it has a date.

What does it cost?

There is no public pricing, because there is no hosted plan to price. The self-hosted version costs you a server — 2 vCPU and 4 GB of RAM is comfortable.

We would rather have no pricing page than an invented one.

Is it open source?

No. A license has not been chosen, so Refficks is described as self-hosted and not as open source. Those are different promises and only the first one is true today.

Do you have compliance certifications?

No, and we are not going to name one we are “working towards”.

What exists are practices you can verify in the code you are running: multi-tenant isolation with a test on every resource; append-only events, attributions, commission entries and audit logs, with who did what, when, and the values on both sides; no raw IP addresses stored anywhere; payout details encrypted at rest and never displayed back to anyone.

If your procurement process requires a certification, Refficks does not meet that requirement today.

Who else is using it?

There are no named customers, no user counts and no usage statistics, because there are none yet. This is an early product.

What we offer instead of proof we do not have: run php artisan refficks:demo after installing, and you get six partners with four months of history built through the real pipeline — the same code path your live data would take. Everything on this site is a screen you can reach in that dataset within a few minutes.

What happens when a customer refunds?

A reversal is written beside the original commission entry. The original is not edited, not deleted and not recalculated — it is still there, with the arithmetic that produced it, and the reversal sits next to it with its own reason.

The same rule holds everywhere: history is never edited. Not a commission, not an attribution, not a raw event. Corrections supersede; they do not overwrite.

What if I send the same event twice?

You get the original result back. Duplicates are structurally impossible to process twice — idempotency is enforced by the database, so a retried webhook or a double-submitted event resolves to the original rather than creating a second commission.

Precisely: this means at-least-once delivery is sufficient for your queue, and you do not need a reconciliation job hunting for duplicate entries. Details for developers.

My affiliate sends traffic that never clicks a link. Can I still credit them?

Yes. A coupon code attributes a sale even when no click ever happened — which covers the podcast mention, the printed card and the community post nobody clicked through.

And if you use Stripe, sales can attribute through Stripe’s own client_reference_id, so a merchant running no JavaScript at all can still credit partners.

How long does it take to set up?

DNS to signed-in in under an hour, with HTTPS issued automatically during setup. Three commands: clone, run the setup script, bring the stack up.

Precisely: Laravel with MySQL and Redis for the API, Next.js for the dashboard and portal. A complete OpenAPI specification, 90 paths, ships in the repository.
